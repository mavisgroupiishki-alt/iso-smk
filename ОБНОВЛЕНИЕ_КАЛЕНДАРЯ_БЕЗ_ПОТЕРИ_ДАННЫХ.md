# Обновление календаря без потери текущих задач

## Главное

Эта версия меняет только файлы интерфейса приложения. Она не удаляет, не очищает и не пересоздаёт данные в Supabase.

Все уже внесённые проекты, этапы, комментарии, ссылки и задачи остаются в существующих таблицах.

## Перед обновлением

Для максимальной страховки можно открыть Supabase → Table Editor → `tasks` → Export CSV. Это необязательный, но полезный ручной снимок.

Не запускайте заново полные файлы `supabase.sql` и импортные SQL-файлы, если данные уже находятся в базе.

## Как обновить

1. Замените файлы приложения в GitHub содержимым этого архива.
2. Не меняйте существующие переменные Render:
   - `VITE_SUPABASE_URL`
   - `VITE_SUPABASE_ANON_KEY`
3. Запустите новый Deploy в Render.
4. После статуса Live откройте приложение и нажмите «Обновить».
5. Проверьте количество проектов и задач в верхней части дашборда.
6. Для теста переместите одну некритичную задачу на другое время и обновите страницу.

## Как работает защита

- Календарь обновляет только поля `deadline`, `start_time`, `end_time` одной выбранной задачи.
- Идентификатор задачи, проект, этап, ответственный, статус, комментарий и ссылка не меняются.
- При ошибке Supabase задача возвращается на старое место.
- Перед каждым перемещением сохраняется локальный снимок последних данных.
- Кнопка «Резервная копия» скачивает полный JSON текущего состояния.

## SQL

Для календаря с перетаскиванием новый SQL не нужен.
