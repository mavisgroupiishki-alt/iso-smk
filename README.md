# MAVIS GROUP — центр проектов и задач

Обновлённый React-дашборд для управления работой команды:

- структура **Проект → Этап → Задачи**;
- раскрывающиеся проекты и этапы;
- автоматический прогресс проекта и этапа;
- дедлайны, ответственные, статусы, приоритеты и комментарии;
- отдельный журнал всех переносов дедлайна;
- отдельный список задач, перенесённых с текущей недели;
- отображение старой и новой даты, времени переноса, автора и причины;
- календарь недели;
- общий список задач;
- график загрузки сотрудников;
- создание и удаление сотрудников из интерфейса;
- импорт проекта из Excel в формате `Этап / Задача / Дедлайн / Ответственный / Статус / Комментарий`;
- локальный режим или общая база Supabase;
- деплой через GitHub + Render.

## Что изменилось в логике

### 1. Проект

У проекта есть:

- название;
- описание;
- ответственный;
- общий дедлайн;
- статус;
- цвет;
- автоматический прогресс по завершённым задачам.

### 2. Этап

Внутри проекта можно создавать этапы. У этапа есть:

- название;
- номер/порядок;
- ответственный;
- дедлайн;
- описание;
- автоматический статус и прогресс по задачам.

### 3. Задача

Задачу можно связать с проектом и этапом. Для каждой задачи доступны:

- дедлайн;
- время начала и окончания;
- ответственный;
- статус;
- приоритет;
- трудозатраты в часах;
- измеримый результат;
- рабочий комментарий.

Статусы:

- Ожидает;
- Новая;
- В работе;
- На проверке;
- Блокер;
- Готово.

## Как работает контроль переносов

При редактировании существующей задачи измените дедлайн. В форме автоматически появится блок:

- старая дата;
- новая дата;
- кто перенёс;
- причина переноса.

После сохранения запись попадает во вкладку **«Переносы»**.

Там есть три режима:

1. **С текущей недели** — задачи, чей старый дедлайн находился в текущей неделе, а новый срок стал позже конца недели.
2. **На следующую** — только задачи, перенесённые именно на следующую календарную неделю.
3. **Вся история** — все изменения дедлайнов.

Неделя считается с понедельника по воскресенье.

## Настройка существующего Supabase

Для уже работающего проекта выполните один новый файл:

```text
supabase_projects_update.sql
```

Откройте:

```text
Supabase → SQL Editor → New query
```

Вставьте содержимое файла и нажмите **Run**.

Файл создаёт:

- таблицу `projects`;
- таблицу `project_stages`;
- таблицу `task_reschedules`;
- поля `project_id`, `stage_id`, `comment` в таблице `tasks`;
- индексы и политики доступа;
- замену имени Алиса → Саша в старых задачах.

Для нового Supabase можно сразу выполнить полный файл:

```text
supabase.sql
```

## Локальный запуск

```bash
npm install
npm run dev
```

Создайте `.env` на основе `.env.example`:

```bash
VITE_SUPABASE_URL=https://YOUR_PROJECT_ID.supabase.co
VITE_SUPABASE_ANON_KEY=YOUR_SUPABASE_ANON_KEY
```

Без `.env` приложение работает локально и сохраняет данные в браузере.

## Деплой на Render

1. Загрузите проект в GitHub.
2. В Render создайте **Static Site**.
3. Build Command:

```bash
npm install && npm run build
```

4. Publish Directory:

```text
dist
```

5. Добавьте переменные окружения:

```bash
VITE_SUPABASE_URL=...
VITE_SUPABASE_ANON_KEY=...
```

## Импорт проекта из Excel

Во вкладке **«Проекты»** нажмите **«Импорт таблицы»**.

Поддерживаемые заголовки:

```text
Этап | Задача | Дедлайн | Ответственный | Статус | Приоритет | Комментарий | Результат
```

Название загруженного файла становится названием нового проекта. Уникальные значения в колонке «Этап» превращаются в этапы, строки — в задачи.

В архиве есть пример:

```text
Шаблон_импорта_проекта.csv
```

## Важно

В текущей версии Supabase используется простой MVP-доступ: любой человек со ссылкой на приложение может работать с данными. Для закрытого корпоративного использования следующим этапом лучше добавить авторизацию и роли.


### Комментарии и материалы задачи

У каждой задачи есть редактируемый комментарий и отдельная рабочая ссылка. Ссылка хранится в поле `tasks.resource_url` и открывается из карточки задачи в новой вкладке.
Для существующей базы один раз выполните `supabase_task_links_update.sql`.

## Перетаскивание задач в календаре

Во вкладке **«Календарь»** можно:

- перетаскивать задачу с одного дня и времени на другое;
- брать задачи без назначенного времени из левой колонки и ставить их в календарь;
- перетаскивать задачу обратно в блок «Снять время с задачи»;
- переносить задачу на другой день с автоматической записью в журнал переносов;
- планировать с шагом 30 минут.

Для этой функции **не требуется SQL-миграция**: используются существующие поля `deadline`, `start_time` и `end_time` таблицы `tasks`.

### Защита данных

Обновление интерфейса не очищает и не пересоздаёт таблицы Supabase. При перемещении изменяется только выбранная задача.

- Перед каждым переносом приложение сохраняет локальный снимок текущих задач.
- Если Supabase вернул ошибку, задача автоматически возвращается на прежнее место.
- В шапке есть кнопка **«Резервная копия»**, которая скачивает проекты, этапы, задачи, сотрудников и историю переносов в JSON.
- Локальная копия больше не перезаписывается пустым массивом во время первоначальной загрузки приложения.

## Иерархия разделов

Актуальная структура приложения:

**Раздел → Проект → Этап → Задача**

Для обновления существующей базы без потери данных выполните файл:

`supabase_hierarchy_sections_update.sql`

После миграции проект можно перемещать между разделами из формы проекта или выпадающим списком в карточке. В каждом разделе доступен отдельный фильтр статусов задач.
