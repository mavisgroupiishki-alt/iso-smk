# Технический план: Отзывной доступ сотрудницы

**Спека:** [spec.md](spec.md)
**Создан:** 2026-09-15

## Технологии

Python standard library: `hashlib.scrypt`, `secrets`, HMAC, HTTP-only SameSite cookie и JSON-файлы в Persistent Disk. Внешние сервисы и зависимости не добавляются.

## Архитектура

`users.json` хранит роли, статус и scrypt-хеши; `sessions.json` хранит случайные сессионные идентификаторы с ограниченным сроком. HTTP-обработчик определяет пользователя из cookie перед каждым маршрутом и проверяет разрешение. Задачи и записи журнала получают `owner_user_id`; это предотвращает доступ оператора к старым и чужим результатам.

## API / интерфейсы

- Открытые: `POST /api/auth/login`, `POST /api/auth/logout`, `GET /api/auth/session`, `GET /api/version`.
- Владелец: `GET|POST /api/users`, `POST /api/users/create`, `POST /api/users/update`, `POST /api/users/delete`.
- Оператор: только анализ файлов, архивов, ИИ-чат, генерация, принадлежащие ему задачи и ZIP.
- Экран входа появляется до приложения. В режиме оператора интерфейс оставляет только «ИИгорь Оформитель» и кнопку выхода.

## Риски

- Без `IGOR_OWNER_PASSWORD` безопасный запуск невозможен; production не должен открывать данные до задания переменной.
- Работник может сохранить ZIP, сформированный до отключения; это технически неотзываемо.
- Старые записи журнала без владельца считаются доступными только `owner`.

## Проверка конституции

- [ ] Сервер, а не UI, запрещает закрытые маршруты.
- [ ] Operator использует минимально необходимый набор маршрутов.
- [ ] Отключение проверяется для каждой сессии.
