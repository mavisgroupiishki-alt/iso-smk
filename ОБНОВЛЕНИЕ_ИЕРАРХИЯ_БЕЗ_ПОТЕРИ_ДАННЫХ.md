# Обновление иерархии без потери данных

Новая структура приложения:

**Раздел → Проекты → Этапы → Задачи**

## Что изменяет SQL

Файл `supabase_hierarchy_sections_update.sql`:

- добавляет проекту поле `section_id`;
- сохраняет ответственного и заказчика проекта;
- сохраняет совместимость со старыми отдельными задачами разделов;
- не удаляет и не очищает ни одной таблицы;
- не изменяет названия, статусы, комментарии, ссылки, дедлайны и ответственных задач.

## Безопасный порядок обновления

1. В текущем приложении нажать **«Резервная копия»**.
2. В Supabase открыть **SQL Editor → New query**.
3. Вставить содержимое `supabase_hierarchy_sections_update.sql`.
4. Нажать **Run**.
5. В Results проверить:
   - `projects_before = projects_after`;
   - `stages_before = stages_after`;
   - `tasks_before = tasks_after`;
   - `project_section_ready = true`;
   - `customer_ready = true`.
6. Только после этого загрузить новую версию в GitHub и выполнить Deploy в Render.

## Как перемещать проекты

Проект можно поместить в раздел двумя способами:

- открыть проект на редактирование и выбрать поле **«Раздел»**;
- выбрать раздел в выпадающем списке прямо в карточке проекта.

Перемещение проекта не меняет его этапы и задачи.
