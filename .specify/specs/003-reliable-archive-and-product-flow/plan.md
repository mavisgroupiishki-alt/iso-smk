# Технический план: надёжное чтение архивов и явный выбор продукта

**Спека:** [spec.md](spec.md)
**Создан:** 2026-10-09

## Технологии

Текущий Python-сервер, Persistent Disk, браузерный интерфейс, Tesseract и существующий внешний сервис распознавания. Новая платная инфраструктура не включается без отдельного разрешения.

## Подтверждённые исходные факты

- Сервисы Кристины и Насти действительно отдельные: `iso-smk-kristina` и `iso-smk-rar`; у каждого собственный диск и лимит 512 МБ.
- В каждом сервисе работает один процессор архива. Это исключает конфликт между этими двумя приложениями, но не ускоряет тяжёлый архив внутри одного приложения.
- В текущем коде PDF обрабатывается последовательно. Для кадрового скана предусмотрены попытки без поворота, с поворотом на 90° и на 270°; каждая ожидает до 60 секунд. Именно этот путь дал многоминутные задержки на страницах архива «лидинг (3)».
- Зафиксированы перезапуски процесса по лимиту памяти 512 МБ. Одна только смена лимита памяти не исправит повторные 60-секундные запросы и неверный пакет.

## Архитектура

```
Выбор продукта → карточка заявки → архивная задача
                                      │
                         инвентарь файлов и страниц
                                      │
              быстрый локальный разбор → доказательства полей
                                      │
        только сомнительные страницы → ограниченное точное чтение
                                      │
          карточка с источниками и элементами проверки
                                      │
           манифест продукта/режима → генератор пакета → проверка
```

1. Выбор продукта становится источником правды. Чат получает продукт как контекст, но не может его изменить.
2. Архивная задача хранит пофайловый и постраничный результат в своей записи. Обработанные страницы не отправляются снова после рестарта или дедлайна.
3. Внешнее распознавание вызывается только для страниц, которые не дали пригодного локального текста. Для каждой страницы допускается один компактный повтор; повороты выбираются по предварительной проверке изображения, а не запускаются все подряд.
4. У задачи есть неизменяемый дедлайн 30 минут. По нему возвращается частичный, но пригодный для просмотра результат; очередь не удерживается бесконечно.
5. Критичные факты формируются детерминированным извлечением из источников и связаны с `filename/page`. Модель может предлагать классификацию, но не может слить конфликтующие личности или заполнить пустой факт.
6. Генераторы получают профиль продукта и режим пакета из карточки и проверяют манифест до создания ZIP.

## Изоляция и ресурсы

На текущем этапе отдельные сервисы Кристины и Насти сохраняются. Каждому нужен тот же лимит 30 минут и независимая очередь задач. Для устойчивой обработки крупных сканов потребуется одно из двух решений, которое не выбирается автоматически:

- увеличить память каждого из двух существующих сервисов до 2 ГБ; это снижает риск перезапуска, но не является заменой оптимизации чтения;
- вынести архивный обработчик в отдельный сервис с общей очередью и хранилищем задач; это масштабируется лучше, но требует дополнительного сервиса и переменных доступа.

Сначала реализуются изменения чтения и контроля на текущих сервисах. Решение об оплате инфраструктуры принимается только после замера контрольных архивов.

## API и данные

- `POST /api/extract-archive-async`: принимает явный `product`, `package_mode`, `scope` и создаёт задачу с `deadline_at`.
- `GET /api/task/<id>`: возвращает `file_pages`, `deadline_at`, `remaining_seconds`, `status`, `warnings` и подтверждённые результаты.
- `POST /api/task/<id>/cancel`: сохраняет уже полученное и прекращает новые внешние запросы.
- Карточка: `certification.standard`, `certification.package_mode`, `certification.scope`; критичные поля получают `source` и `needs_review`.
- Манифест: `product + package_mode → required / optional / forbidden documents`.

## Риски

- Неразборчивый рукописный текст может остаться неподтверждённым. Митигация: отображать точную страницу и не подставлять выдуманное значение.
- Сокращение повторов может уменьшить долю прочитанных страниц. Митигация: сначала сохранять локальный результат и повторять только одну подготовленную версию страницы.
- Полный DOCX-пакет может отличаться от ручного образца не только составом, но и макетом. Митигация: отдельные манифестные и визуальные проверки ключевых документов.
- 512 МБ может остаться недостаточно даже после оптимизации. Митигация: измерить максимум на двух реальных архивах до решения о тарифе.

## Проверка конституции

- [ ] Нет неподтверждённой «готовности»: результат каждой стадии хранится в задаче.
- [ ] Архив заканчивается не позднее дедлайна и не теряет готовые страницы.
- [ ] Пользовательские данные не смешиваются между сервисами и задачами.
- [ ] Реальный внешний прогон отмечается отдельно от тестов с заглушкой.
