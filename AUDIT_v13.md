# Техническая перепроверка кода — v13

## Исправлено в этой версии

1. **Два несвязанных реестра компаний.** Вкладка «Компании» читала `/api/companies`, а ИИгорь сохранял карточки в `/api/kv`. Поэтому вкладка не показывала реальные данные ИИгоря.
2. **Серверное хранилище было временным.** При отсутствии `/data` данные записывались внутрь приложения и исчезали после deploy/restart Render.
3. **Autosave не работал до распознавания названия/УНП.** Черновики могли полностью потеряться.
4. **Ключ строился из названия/УНП.** Исправление названия создавало новую запись и оставляло старую.
5. **Асинхронный fetch при закрытии вкладки ненадёжен.** Теперь перед закрытием выполняется синхронная локальная запись.
6. **Частичные ответы ИИ заменяли целые массивы.** Один обновлённый сотрудник мог удалить остальных; то же относилось к объектам и поставщикам.
7. **СПК/ISO-СУОТ данные не имели устойчивого структурированного места.** Добавлены `spk`, `iso_suot`, `source_documents`.
8. **Excel `[Лист: ...]` ошибочно помечался как ошибка чтения** внутри вложенных ZIP/RAR.
9. **Неатомарная запись JSON.** При остановке процесса файл мог остаться пустым или обрезанным.
10. **Render устанавливал только две зависимости.** `render.yaml` переведён на `pip install -r requirements.txt`.

## Проверено

- Python-файлы компилируются без синтаксических ошибок.
- JavaScript из `index.html` проходит `node --check`.
- Пройдены актуальные тесты аттестации v8 и универсального жёлтого выделения v12.
- Добавлены отдельные тесты сохранения полной карточки на frontend и backend.
- Проверено сохранение/восстановление реквизитов, сотрудников, объектов, поставщиков, СИ и ТТК.

## Отдельные содержательные риски, не скрытые этой версией

Эта версия исправляет хранение и потерю данных. Она не делает автоматически универсальными сами шаблоны:

- ISO/СУОТ всё ещё основан на пакете компании-образца и требует дальнейшей содержательной переработки ролей, дат, области деятельности и отбора инструкций;
- СПК в старых ветках генератора содержит резервные типовые ТТК и СИ; их нельзя считать фактическими данными клиента;
- серверные KV-endpoint сейчас не имеют отдельной авторизации. Если приложение доступно по публичной ссылке, нужен отдельный этап защиты доступа;
- общий реестр для разных компьютеров требует Render Persistent Disk или внешнюю БД. Browser localStorage работает только в конкретном браузере.
